# TraceStory Deployment

> [!NOTE]
> The database migration and Render/Vercel deployment configurations have been fully prepared locally, but the live services are not yet deployed to production hosting servers.

This document provides guidelines for deploying the TraceStory backend and frontend services to production hosting providers.

## Architecture

```
[ Vercel Client App ]
        │ (React UI / HTTP Requests)
        ▼
[ Render FastAPI Backend ] ◄──────────► [ Groq LLaMA API ] (AI Summaries)
        │
        ▼
[ Render PostgreSQL Database ]
```

---

## Environment Variables

### Backend Configuration (Render)

*   `DATABASE_URL`: Connection URL for the PostgreSQL database instance. 
    *   *Format*: `postgresql+psycopg://username:password@host:port/database`
    *   *Note*: The application automatically normalizes `postgres://` or `postgresql://` links generated by Render to use the `psycopg` (v3) driver.
*   `GROQ_API_KEY`: API token used for LLM classification, summarization, and RCA queries.
*   `FRONTEND_ORIGIN`: URL of the deployed Vercel frontend app. Used to allow secure cross-origin (CORS) requests. Comma-separated strings are supported for multiple origins. Default is `http://localhost:3000`.

### Frontend Configuration (Vercel)

*   `REACT_APP_API_URL`: Public URL of the deployed FastAPI backend. Used by React components to perform HTTP queries.

## Local PostgreSQL Setup

Follow these steps to run a local PostgreSQL database for development:

1.  **Start PostgreSQL service**: Make sure PostgreSQL is installed and active on your system.
2.  **Create the Database**:
    Open an interactive shell (`psql`) and run:
    ```sql
    CREATE DATABASE tracestory;
    ```
3.  **Configure environment**:
    In your local `.env` file, update the `DATABASE_URL` line:
    ```env
    DATABASE_URL=postgresql+psycopg://postgres:your_password@localhost:5432/tracestory
    ```
4.  **Run backend**: When started, the backend will automatically initialize the database schema and tables (`spans`, `trace_summaries`, `incidents`).

## Backend Setup (Render)

1.  **Create PostgreSQL Database**:
    *   Provision a new database service on Render.
    *   Note the **Internal Database URL** (used if both services are in the same region) or **External Database URL**.
2.  **Create Web Service**:
    *   Connect your GitHub repository.
    *   Configure the runtime environment as **Python**.
    *   Set the **Build Command**:
        ```bash
        pip install -r requirements.txt
        ```
    *   Set the **Start Command**:
        ```bash
        uvicorn backend.main:app --host 0.0.0.0 --port $PORT
        ```
3.  **Configure Environment Variables**:
    Under the **Environment** tab, set:
    *   `DATABASE_URL` (to the database URL obtained above)
    *   `GROQ_API_KEY`
    *   `FRONTEND_ORIGIN` (to your vercel app domain)

---

## Frontend Setup (Vercel)

1.  **Configure project**:
    *   Import the repository into Vercel.
    *   Set the **Root Directory** to `frontend`.
2.  **Configure Environment Variables**:
    *   Add `REACT_APP_API_URL` pointing to the production Render FastAPI backend URL (without trailing slash).
3.  **Deploy**: Succeeded deployments will serve the static React files on a Vercel URL.

## Verification

To verify that the production deployment works correctly:

1.  **Health Check**:
    Fetch the health endpoint:
    ```bash
    curl https://your-backend.onrender.com/health
    ```
    *Expected output*: `{"status": "ok"}`
2.  **Telemetry Ingestion**:
    Post a test payload to `/api/ingest`:
    ```bash
    curl -X POST https://your-backend.onrender.com/api/ingest \
      -H "Content-Type: application/json" \
      -d '{"spans": [{"trace_id": "v-1", "span_id": "s-1", "parent_id": null, "service_name": "gateway", "operation_name": "ping", "duration_ms": 10.0, "status": "OK", "attributes": {}}]}'
    ```
3.  **Trace Fetch**:
    Fetch the traces list to confirm persistence:
    ```bash
    curl https://your-backend.onrender.com/api/traces
    ```
